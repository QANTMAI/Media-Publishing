## 1. Overall posture

The core is genuinely well-built and **appropriate for a single operator**:
alg-pinned JWT + real epoch revocation, monotonic-step TOTP replay defense (DB
CAS, multi-instance-safe), AES-256-GCM vault with no plaintext leak, method/key/
expiry/byte-bound signed URLs with timing-safe compare, streamed byte-cap uploads
with traversal-proof keys and argv-based ffmpeg, a durable DB-backed queue with
an atomic claim, `npm audit --omit=dev` = **0 vulns**, and clean sensitive-data
logging. The real work is a small set of **security hardening**, **operational
durability**, **process (CI)**, and **product-completeness** items below.

## 4. Dependency-aware gap list — the SOTA vertical slice

Target slice: **FIND event → evidence bundle → suggested canonical content → channel repurposing → human review → scheduled publishing → analytics.** Current maturity + gaps, ordered so each Pn unblocks the next.

| Stage | Today | Gap | Priority |
|---|---|---|---|
| **FIND event** | Operator RSS/Atom feeds (`feeds.ts`), worker-polled ~3h | **S1 SSRF hardening** (blocks safe cloud deploy); discovery is RSS-only (no trends/news/social-listening) | **P0** (S1) / P2 (breadth) |
| **Evidence bundle** | Memory projections (episodic/eval) + distillation evidence, cited | Evidence is audit/metric-derived; no cross-source enrichment | P2 |
| **Suggested canonical content** | **Not built** — distillation produces *learnings*, not draft content; autopilot captions are canned `"Draft ·"` | **AI content generation** (the key seam `getCredentialPlaintext` is proven by distillation) — the biggest *product* gap | **P1** |
| **Channel repurposing** | Publisher formats *media* per platform (IG portrait/Reel, YT video, BS images); no per-platform *caption/content* adaptation; per-platform overrides deferred | Per-platform caption/format repurposing from one canonical draft | **P1** |
| **Human review** | **Built** — autopilot review mode → draft (no job) → `/approve` transaction; memory drafts → approve | Solid; extend approval to AI-generated content when it lands | keep |
| **Scheduled publishing** | **Built + durable** — DB queue, atomic claim, retry/backoff, 5 real channels | **P0 reliability set:** external idempotency key + tighter double-publish window (T2), `(post,account)` uniqueness + `accountIds` dedup, DLQ visibility; **P1:** publish-side rate limiting, backoff cap+jitter, worker audit `userId`, token refresh + `expiring`, post-level rollup, Meta timeouts | **P0/P1** |
| **Analytics** | **Built for IG/FB** (real MetricSnapshot via Graph); none for LinkedIn/Bluesky/YouTube | Metric collectors for LinkedIn/Bluesky/YouTube; app-level observability (R2) | **P1** |

### P0 — do first (correctness / security / data-safety / enables trust)
1. **S1 SSRF hardening** (FIND) — before any non-loopback deploy.
2. **Publish idempotency** — external idempotency key + close the first-bookkeeping-write-fails window (silent duplicate posts). Depends on a schema field.
3. **`(post,account)` uniqueness + `accountIds` dedup** (scheduled publishing) — DB-level duplicate-job prevention. Schema migration.
4. **CI gates** (T1) — cheapest, protects every other fix from regressing.
5. **Backups automation + DR runbook** (R1) — data-loss risk; `db:backup` script + key-restore step.

### P1 — important, sequenced after P0
- AI **content generation** (canonical content) + **channel repurposing** — the product core of the slice; unblocked by the vault key seam that distillation already uses.
- Publish-side **rate limiting** + **backoff cap/jitter**; **worker audit `userId`**; **token proactive refresh + real `expiring` transition**; **post-level partial-published rollup**; **Meta fetch timeouts** (R3).
- **AI distill rate/cost cap** (A1); untrusted-text labeling (A2).
- **Analytics** collectors for LinkedIn/Bluesky/YouTube.
- **Tests:** worker idempotency/reclaim (T2), retry/paused transitions (T5), Meta OAuth (T4), per-platform contract tests (T3/T7), cross-user isolation (T6).
- **Structured logging** for the CRITICAL path (R2).

### P2 — scaling / polish / future
- DLQ as a first-class queryable surface; side-loops on own intervals (R4).
- `/metrics` (queue depth) + tracing; CSP nonce (S3); `/setup` throttle (S4); Origin check (S5).
- Memory `userId` scoping (S2) — only if/when multi-operator (P4 of the memory plan).
- Horizontal scaling: dedicated worker process + DB/Redis rate limiter (R5); load tests (T8).
- FIND breadth (trends/news/social listening).
